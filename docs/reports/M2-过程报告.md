# 项目过程报告 · M2 RAG 知识库与前端闭环

> 所属阶段：**M2（RAG 知识库与前端闭环，原 M2+M3 合并）**｜执行日期：2026-09-23 ~ 2026-09-24
> 阶段范围按产品经理 2026-09-23 指令调整：RAG 知识库与前端优先合并交付，Agent 顺延至 M3（见 ROADMAP 变更记录）。

## 1. 这阶段做了什么

- **数据层**：`kb_groups` / `documents` / `chunk_fingerprints` 三表（models + init_db.sql 双份 DDL 对齐）+ CRUD。设计要点：(user_id, group_id, file_name) 唯一 = 同名重传视为版本更新走增量；`empty_pages` 登记无文本层页码（M4 OCR 的工作清单）；块指纹存 (chunk_index, chunk_hash) 作为增量比对基线。
- **入库链路（app/ingest/）**：PDF（真实页码）/ Word（约 1000 字符逻辑页，段落不拆）/ PPT（幻灯片序号）三解析器统一成 ParsedPage；页感知滑窗切块（**块绝不跨页**，溯源根基）；两级 sha256 指纹（文件级短路 + chunk 级 added/changed/removed/unchanged 四分类）；`ingest_file` 状态机（幂等短路 → 解析 → 切块 → diff → 只向量化变化块 → 指纹整组替换 → 失败留痕 status=failed）。
- **RAG 读路径（app/rag/）**：VectorStore 接口 + ChromaStore（collection 按 `u{user}g{group}` 物理隔离；显式传 embeddings 禁用 chroma 默认 EF 防断网翻车；score=1-余弦距离）；检索器（跨分组合并 → 阈值过滤 → top_k）；prompts（四条铁律 system + **sanitize 删模型伪来源** + **append_sources 强制拼接【来源：文件名，第X页】** + 兜底话术）。
- **接口层**：`/kb/*`（分组 CRUD/上传/文档列表/删除，级联清 DB+文件+向量，越权一律 404 防探测）；`/chat/ask`（**空检索直接兜底且严禁调 LLM**——防幻觉硬闸门）。
- **前端（Streamlit 1.64）**：登录/注册门 + `st.navigation` 多页面（上传管理：增量计数可视化、扫描页登记提示；智能答疑：对话式提问 + 来源卡片 + 兜底样式）；`services/api.py` 统一错误翻译。
- **测试与演示**：新增 37 项单测（解析/切块/指纹/检索/溯源/接口，全量 56 passed）；`scripts/demo_e2e.py` 端到端自检脚本；README 补双终端启动命令。

## 2. 遇到了什么问题

1. **后台编排两次停摆**：用户在会话中按 ESC/中断，连带杀掉后台工作流的子智能体（日志留痕 `[Request interrupted by user]`），编排等一个已死智能体永远停滞；且工作流前端智能体陷入「过度调研」（40 分钟读 Streamlit 源码不落一个文件）。
2. **层间契约偏差**：契约里 `ChromaStore.upsert` 是同步签名，但「显式向量化禁用默认 EF」必须经 gateway 异步接口，只能做成 `async`。
3. **conftest 假向量不可 await**：`_AwaitableVectors` 双形态类定义了但 `_fake_embed_fn` 返回裸 list，`await embed_texts(...)` 会 TypeError。
4. **手工构造测试 PDF 的 xref 表条目数少 1**：声明 `0 count` 但实际写 count+1 条（0 号空闲条目也占一条），pypdf 报 `Could not read Null object`。
5. **Streamlit 1.64 与 ROADMAP 目录名冲突**：官方多页面文档明确警告 `pages/` 会与旧版自动发现机制冲突，页面目录必须避开该命名。
6. **skill 发现脚本在 Windows 找错解释器**：`python3` 命中 Microsoft 商店占位壳（无 streamlit），真解释器是 `python`（Python311）。

## 3. 怎么解决的问题

1. 取证确认停摆根因（journal 最后一行即中断标记、文件 mtime 长期不动）后用**断点续跑**恢复（已完成智能体走缓存零重跑）；对超时智能体设定「10 分钟不见文件即接管」的止损线，前端 5 文件由主循环亲手交付（含 Streamlit 官方 skill 规范）；后续阶段按产品经理「你亲自来吧」指令全部收回主循环执行。教训入库：**后台多智能体适合可并行的独立文件批产，不适合需要持续值守的长链路**；ESC 中断会连带杀后台任务，交互提问用打字。
2. 接受偏差并让契约对齐现实：`upsert` 改 async（参数表不变），并在 vector_store docstring 写明原因（显式 embeddings 是断网保命红线，异步是它的必然代价）；集成阶段按实际代码对齐测试。
3. 修复 conftest：`_fake_embed_fn` 返回 `_AwaitableVectors(vectors)`，同步取值与 `await` 两种用法都成立（保留原设计意图）。
4. 按 PDF 规范补上「xref 条目数 = 对象数 + 1（含 0 号空闲条目）」——一行修复后全绿；手工拼 PDF 的方法留档在测试辅助函数里，避免为测试引入 reportlab 等计划外依赖。
5. 页面目录改 `frontend/app_pages/`（文件名不变），偏离 ROADMAP 目录名的原因与证据写入本报告与代码注释——这是框架版本硬要求，功能零变化；答辩演示如被问到目录结构以实际仓库为准。
6. skill 发现脚本用 `PATH` 临时剔除 WindowsApps 再跑，落到真解释器；顺带把「Windows 双解释器坑」记入排障素材。
7. 测试纪律执行：单测零网络零磁盘（EphemeralClient + n-gram 哈希假向量）；防幻觉分支用「LLM 一旦被调用即 AssertionError」的硬校验；越权用 A/B 双用户对照测 404。遗留一项已知待办：`SCORE_THRESHOLD=0.35` 为默认值，待 3 正例/3 负例标定后回填 `.env`（原 M3 既定计划，不影响闭环演示）。
