# M4 过程报告 · Agent 智能调度与多轮增强

> 所属阶段：M4（tag `M4-agent`）｜完成日期：2026-09-24｜单测：120 passed

---

## 一、这阶段做了什么

**交付物：Agent 编排层（`app/agent/`）+ 短期记忆（`app/memory/short_term.py`）+ 前端试题卡与引导式开关，测试 81 → 120。**

1. **LangGraph 状态图**（`app/agent/graph.py`）：`start(计算旁路/query改写) → retrieve(检索) → classify(意图分类) → qa|quiz|summary|calc | fallback`，条件边路由，四工具节点直连 END。
2. **意图分类**（`app/agent/intent.py`）：单标签枚举 + 温度 0 + 输出 ≤16 token + few-shot；非法输出一律回退 `qa`（路由永不卡死，风险预案 R3 落地）。
3. **四个工具**（`app/agent/tools.py`）：
   - 答疑：自 `chat.py` 原样平移（防幻觉三层防线、资料不足闸门、来源强制拼接语义未动），新增引导式答疑（苏格拉底模式）system 开关；
   - 出题（含随堂测）：强制 JSON 结构输出 → `parse_quiz` 严格校验；**answer 本体即 JSON，溯源由 sources 字段独立承载（绝不往 JSON 里拼【来源】）**；
   - 总结：要点列表模板 + 同款闸门/净化/拼来源；
   - 计算：正则整句识别算式（全角转半角、剥离引导词）→ AST 白名单安全求值（只认数字与四则/幂，名字/属性/调用结构级拒绝，幂指数与结果双上限）→ LLM 仅生成步骤并被明令禁止重算结果。
4. **短期记忆**（`app/memory/short_term.py`）：滑窗读 `messages` 表最近 `SHORT_TERM_WINDOW=6` 条（配置进 `.env`）；query 改写独立小调用（输出 ≤96 token、温度 0），**无历史零调用**；改写失败/空输出回退原问题。
5. **接口瘦身**（`app/api/chat.py`）：只做鉴权/会话/分组校验 → `run_agent` → 落库；`AskRequest` 增 `guide_mode`；响应增 `intent`；新增 `POST /chat/score` 判分（单选代码层精确判零 LLM、简答 LLM 按要点判、解析失败 502 绝不给假分）。
6. **前端**：答疑页加意图徽章（活体显示）、引导式答疑 toggle、输入框提示语更新；新组件 `components/quiz.py`（试题卡：作答/判分/标准答案折叠，活体与回看同一渲染路径，按内容 JSON 特征识别试题）。
7. **测试**：新增 `test_intent.py` / `test_short_term.py` / `test_agent_tools.py` / `test_agent_graph.py` 四文件 + 既有两文件补丁缝迁移，共 120 项全绿。

**本阶段最关键的设计决策——「检索前置」**：意图分类若放在检索之前，分类这一次 LLM 调用会击穿「空召回零调用」的字面属性（单测硬断言 `calls==0`、答辩核心卖点）。最终布局把分类放在检索命中之后、计算用正则旁路放在检索之前——两条性质都保住：无关问题一个模型都不碰，纯算式不依赖知识库。

**教学特色包吸收**：随堂测 = 出题工具（道数由模型从提问读取，零额外参数）；引导式答疑 = 答疑 system 追加第 5 条铁律（默认关）。

**显存红线自查**：单轮最多 3 次顺序 LLM 调用（改写 ≤96 / 分类 ≤16 / 生成 ≤512+），全部经既有 `Semaphore(1)+Lock` 串行排队；零并发推理、零新增常驻模型。

## 二、遇到了什么问题

1. **`prompts.py` 的 `_QUIZ_SCHEMA` 括号未闭合**——首次导入冒烟直接 `SyntaxError`。
2. **Streamlit 1.64 的 `st.radio` 没有 `accept_none` 参数**——按旧版习惯传参会 `TypeError`。
3. **答疑页出现两段重复的 `except ApiError`**——批量编辑时同一段被追加了两次，第二段是永不执行的死代码。
4. **`build_score_prompt` 的 zip 解包写成 3 元组但只传 2 个序列**——`ValueError: not enough values to unpack`，两个判分测试连挂。
5. **滑窗测试造数翻倍**——`append_message_pair` 一次写两条（问+答），造数函数却按「条数」逐次循环，8 变 16，窗口断言错位。
6. **测试补丁缝整体搬家**——问答逻辑迁出 `chat.py` 后，13 处 `app.api.chat.gateway/retrieve` 补丁会 `AttributeError` 或静默失效（打在无人调用的命名空间上，测试照过但没验到）。
7. **`tools.py` 的 `Sequence` 类型标注导入放在函数之后**——注解在定义时求值，导入即 `NameError`（自查发现，未上测试台）。
8. **架构决策反复**：分类先行会破坏「空召回零调用」；计算工具若排在检索后会被空召回兜底「误杀」（纯算式通常检索不到课件）。
9. **试题的 intent 回看丢失**：`message` 表无 intent 列，`create_all` 不会给已有表加列（SQLite/MySQL 双份迁移）。

## 三、怎么解决的问题（与上一一对应）

1. 读文件定位缺失的右括号，补上后重跑导入冒烟（并把「写完立刻 `python -c` 导入」固化为大文件写作习惯）。
2. `inspect.signature(st.radio)` 实测 1.64 签名：`index=None` 已原生支持返回 None，删掉 `accept_none` 参数即可——**框架 API 以本机实装签名断言，不凭记忆写**。
3. 重读文件尾部定位重复段，合并为单个 `except` 并补 `st.rerun()`（成功/失败路径统一走渲染循环上屏，两路径同构）。
4. zip 改为 `(q, stu)` 二元组，标准答案从题面 dict 取（它本来就在 `q["answer"]` 里）；复跑 120 全绿。
5. 造数循环改为 `n_messages // 2` 轮，注释写明「按条数与滑窗断言同粒度」。
6. 两个既有测试文件加 `_stub_agent`/`_nocall_agent` 助手：生成与分类**分命名空间打桩**（`calls` 只计答案生成）；零调用硬闸门测试把**改写/分类/生成三缝全堵**——任一被调即失败。缝位搬家后「补丁打在没人调用的命名空间」是静默假绿，三堵口诀写进助手 docstring。
7. 导入移回文件顶部。
8. **「检索前置 + 计算正则旁路」**终局布局（模块 docstring 画了完整图）：分类在命中后、算式在检索前——空召回零调用与计算可达性同时成立；测试用「retrieve 一被调就失败」的桩锁死旁路行为。
9. **按内容特征识别试题**（`{"type":"quiz"...}` JSON 前缀）而非加列：零迁移成本；活体回答带 intent 徽章、回看降级（仅试题可识别），限制写进页面与组件注释；M5 `quiz_records` 落表时再正式归档。

**遗留与边界**（已知不处理）：回看历史不显示 qa/summary/calc 徽章（intent 不落库）；判分结果不持久化（刷新即清，M5 随错题本落表）；`SCORE_THRESHOLD` 标定仍为 M2 遗留待办。
